The repository has been built on by many parallel sessions. This page records what a line-by-line review found: withdrawn figures, superseded builds, orphaned pages, a dual publish path, and the corrections made in this pass.

Repository review findings. These rows describe the repository rather than the area, so they cite the page that carries the evidence. Severity is this session's judgement, not an official classification.

Recorded as F-14.Fixed · Jobs

A repository admin can still remove the duplicate run by switching Pages to GitHub Actions (the REST attempt returns HTTP 403 from an integration token).Fixed · This page
RR-06HighTwo deployment paths raced: the branch-based Pages build published the entire repository, while a workflow published a whitelisted subset. Which content was live depended on which finished last.Workflow runs and the Pages branch build both ran on every push to main; the Pages API reported the branch build as the source.The workflow publishes exactly the validated page set plus its assets on every push to main. Both paths currently carry identical dashboard files, so the published pages are correct either way, but the duplicate run is a known, logged defect.Contained · Verification audit
