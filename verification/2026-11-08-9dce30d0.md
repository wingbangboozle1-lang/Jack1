## 3. Publication scope defect and fix

The repository's Pages setting is `build_type: legacy` with source `main` `/`, so the legacy build publishes **every** file in the repository root — superseded dashboards from earlier sessions, the research tree, datasets, and markdown. Several of those stale pages still carry figures this brief has withdrawn (including the $1.355T metro GDP claim), which is exactly the failure mode the privacy/verification rules forbid for a public product. Switching the Pages setting to GitHub Actions returns **HTTP 403 "Resource not accessible by integration"** (third session to hit this; an admin must change Settings → Pages → Source).

Fix applied without admin rights: `_config.yml` now scopes the legacy Jekyll build to the eight pages, `404.html`, `assets/styles.css`, and `assets/site.js`, and `.nojekyll` was removed so Jekyll actually runs as the filter. The nine published HTML pages carry no YAML front matter, so Jekyll copies them byte-for-byte. A local simulation of the exclude rules returns exactly 11 files:

```
404.html assets/site.js assets/styles.css audit.html decision.html
flagged.html index.html market.html property.html risks.html sources.html
```

`404.html` was also rewritten: it previously linked to two competing sites (`pages/…`, `site/index.html`, `risk.html`) and loaded two different stylesheets; it now links only the eight canonical sections. The Pages workflow's artifact step was updated to match, so both publishers now emit the same set.

**Residual risk, disclosed:** if the Jekyll build ever fails, GitHub Pages keeps serving the last successful build; the failure would be visible in `GET /repos/…/pages/builds/latest` and is reversible by restoring `.nojekyll`.
