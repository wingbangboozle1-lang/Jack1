## Privacy check of repository commit metadata

- **Method.** GitHub REST commit listing for `main` (paginated, 262 commits), classifying each author email as a GitHub no-reply address or not. The local clone is shallow (5 commits visible), so the API was used for the full count.
- **Finding.** 161 commits use a GitHub no-reply author address. **101 commits use a personal email address** in author metadata.
- **Where it appears.** Git history of a public repository. It is not on the published site, and the address is not written into any dataset, page or this ledger.
- **Existing flag.** `flag_git_metadata_privacy` (from an earlier session) raised the exposure without a count. This session's `flag_646fddf8_commit_email_privacy` adds the count and the official GitHub references.
- **Sources.** [GitHub Docs: Setting your commit email address](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address) (a changed setting does not alter earlier commits); [GitHub Docs: Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) (rewriting history changes every affected hash, disturbs open PRs and forks, and requires every collaborator to re-clone).
- **Decision.** Not changed by this session. Rewriting history is a destructive, owner-level action.
- **Note on earlier privacy scans.** The QA-1 and earlier scans covered file contents only, not commit metadata. This check closes that gap.
