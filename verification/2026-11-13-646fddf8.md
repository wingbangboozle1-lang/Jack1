## Privacy check of repository metadata (new)

- **Method.** GitHub REST commit listing for `main` (paginated, 262 commits), reading only the author email's domain type, and the GitHub documentation pages below. The local clone is shallow (5 commits visible), so the API was used for the full count.
- **Finding.** 161 commits use a GitHub no-reply author address. **101 commits use a personal email address** in author metadata.
- **Where it appears.** Git history of a public repository. It is not on the published site, and the address is not written into any dataset, page, or this ledger.
- **Sources.** [GitHub Docs: Setting your commit email address](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address) (a changed setting does not alter earlier commits); [GitHub Docs: Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) (history rewrite changes every affected hash, disturbs open PRs and forks, and requires every collaborator to re-clone).
- **Decision.** Not changed by this session. Rewriting history is a destructive, owner-level action. Options are recorded on Flagged for Review (`flag_646fddf8_commit_email_privacy`).
- **Note on earlier privacy scans.** Earlier scans, including QA-1, covered file contents only. They did not cover commit metadata. This is the gap this check closes.
